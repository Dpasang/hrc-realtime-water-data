# 淮河实时水情每日归档

每天北京时间 **17:00** 从[淮河水利委员会水文局首页](http://www.hrc.gov.cn/swj/)读取“实时水情”表格，由GitHub Actions保存原始页面证据、CSV/JSON、每日快照、分站月序列和月统计。仓库为私有，不需要个人电脑保持开机，也不需要额外Cookie或令牌。

## 数据结构

| 路径 | 内容 |
|---|---|
| `data/daily/YYYY-MM-DD/HHMMSS/` | 每次运行的HTML证据、可读CSV/JSON、清单和原始证据压缩包 |
| `data/YYYY-MM/HRC.json` | 该观测月按站点组织的时间序列 |
| `data/YYYY-MM/河流_站名__哈希.csv` | 固定表头的分站月序列 |
| `data/YYYY-MM/月统计.csv` | 逐站逐指标的样本统计 |
| `snapshots/YYYY/MM/YYYY-MM-DD.json/.csv` | 当日最后一次成功抓取 |
| `latest/data.json/.csv` | 最近一次成功抓取；失败运行不会覆盖 |
| `history/wayback/` | Wayback索引、原始历史页面、已恢复表格及核验结果 |

月目录按页面中的**观测时间**归属，每日快照按实际**采集时间**归档。同站同观测时刻反复抓取只计一次；出现不同有效数值时标记冲突、保留原值变体并从月统计排除，不取平均掩盖冲突。

## 当前公开字段

首页表格公开河流、站名、日期、水位、流量和“超警戒/汛限水位”，但当前表头没有注明水位、流量的单位。JSON使用中性字段`water_level_value`和`flow_value`，单位留空并标记`not_stated_on_page`；不得仅凭常见水文惯例把它们写成米或m³/s。

最后一列混合两种标签。负数保留为“低于警戒/汛限阈值的差值”；零值和正值仅保存原值并标注语义未确认，不反推阈值，也不纳入差值月统计。原始HTML和逐行字段同时保留，便于以后按官方说明重新解释。

页面没有公开站号，因此使用“河流+站名”作为精确站点键，不自行补造或模糊合并。2026年10月27日首次验证时页面有8行；行数会随官方页面变化，不能把它当作淮河流域完整站网。

## 历史快照

首次检索到2019—2026年38个内容去重后的Wayback首页快照，其中36个成功恢复水情表，共651个源行，观测时间覆盖2019年7月19日至2026年6月8日。另有一个快照存在必填水位或站名异常，一个快照没有目标表，均保留页面与排除原因。这些是不连续的互联网存档样本，不能当作逐日完整历史序列。

## 月统计边界

月表计算有效样本数、有效日期数、样本均值、最小值、最大值和首末值。它反映已归档的离散时刻样本，不是完整月平均、月径流量或连续洪水过程；不插值、不把缺测填零。`fresh`要求全部行的观测时间距评估时刻不超过48小时，并与页面结构检查是否成功分别报告。

## 本地运行

需要Python 3.12，采集本身仅使用标准库；历史恢复还调用系统`curl`。

```text
python -m unittest discover -s tests -v
python collector.py
python archive.py
python recover_history.py
```

GitHub工作流每天UTC 09:00调度，对应北京时间17:00。GitHub可能排队延迟，文件中保存实际采集时间。公开信息归发布机构所有，本仓库用于可追溯归档。
